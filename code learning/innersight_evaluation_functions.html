InnerSight · Stage 7 · reference

Every function in evaluation/

All 194 of them, in file order, in plain language. One line each.

evaluation/ is the stage that turns six saved models into the numbers the project is submitted on. It reads checkpoints and never trains, never refits a scaling and never re-picks a decision cutoff — all three travel inside the checkpoint files precisely so this stage cannot recompute them by accident. Roughly half the package exists not to produce numbers but to prove the numbers are believable: named checks that print their own evidence, a phase ordering enforced by a missing-file error, and an audit trail for every opening of the test split.

16 files, 194 functions. 88 at module level, 104 methods and properties on the dataclasses, 2 nested inside other functions. test_evaluation.py is 68 of them on its own.

The ★ marks the ones where the real thinking is — 24 across the package. The rest is plumbing, and can be read once and forgotten.

Where the code and its own documentation disagree. Five places, listed here rather than left buried:
  • Corpus.refit_train_standardiser's docstring names guards.standardiser_guard as its only caller. No such function exists — it is guards.standardiser_from_checkpoint, and the test suite calls it too.
  • phase1.py's module docstring says “three of Phase 1's four tasks live here”, then refers to “the fourth and fifth”.
  • phase1.PHASE1_ARTIFACT and phase1.DETECTION_CSV are defined and never read. Both write() and require_phase1() rebuild those paths themselves, so they can add the .sample suffix.
  • Four functions are dead across the whole repository: corpus.as_tensor_labels, corpus.require_no_gaps, falsepositives.is_insider_row and Checkpoint.threshold_choice.
  • load_variant_checkpoint is exercised only by the tests. run_b7 writes w7 checkpoints but never reloads them — which is why the wrong window length stamped onto those files is tolerated rather than fixed.

1__init__.py

Stage 7's contract, written down where the imports are — 0 functions, 67 lines.

The only file in the package with nothing to call: all docstring, plus one __all__ list. What it carries instead is the contract — the five commands in the order they must be run, the rule that Phase 1 must finish in full before the test split is opened, the rule that nothing is refitted or re-swept because the scaling and the cutoff travel inside each checkpoint, and the rule that the losing Model B v2 tuning attempt appears nowhere in the result. Then a table giving each module its one job.

Worth reading before the rest, because nearly every refusal elsewhere in the package is one of those four sentences turned into code.

17The five functions to actually remember

Not the five most complicated. The five where, if you misunderstand what they do, you misunderstand what the project measured.

1
corpus.Corpus.build

Everything downstream is these rows. It takes the scaling as an argument rather than computing one — there is deliberately no path in the module that could fit one on the rows it is about to score — and it re-derives the dates and raw numbers independently of the tensors, then refuses to continue if the two disagree about who owns which row. That refusal is what makes every latency figure a fact rather than a plausible table.

2
checkpoints.load_checkpoint

The brief says the losing v2 tuning attempt must not appear in any comparison. This function makes that survive a tired evening: the filename does not match the pattern, so the path does not load. A rule enforced by a regular expression outlasts a rule enforced by remembering it.

3
scoring.describe_at_threshold

The whole difference between a result and a leak, sitting in one function name. It is handed a cutoff and reports what that cutoff does. Its counterpart in the training code searches for the cutoff that flatters the numbers most, and is pointedly not imported here. Confusing the two produces a better-looking figure and no error at all.

4
guards.not_suspiciously_good

Fails the run when a model scores too well. At a 0.4% positive rate, average precision above about 0.95 means a split applied by row instead of by person, or a label leaking into a feature — not a triumph. It is the only check in the package that fires on the number the project would most like to be true, which is exactly why it is enforced in code and exits non-zero.

5
latency.read_verdict

Decides which of two claims the project may make: that it detects insiders at onset, or that it notices exfiltration campaigns already under way. Its thresholds sit as constants immediately above it, fixed before any of the numbers existed, so the conclusion is a consequence of the measurement rather than a description written to fit it.

The package in one sentence. corpus gets the rows, checkpoints gets the models, scoring multiplies them together — and everything else, the guards, the latency analysis, the false-positive inspection and the phase ordering, exists to establish that the answer means what it appears to mean.
