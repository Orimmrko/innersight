InnerSight · Stage 3 · function reference

Every function in baseline/

All 36 functions across the package, in plain language, in the order the files put them.

This package is Stage 3: it takes the table of raw daily counts and turns every number into a statement about the person who produced it. "Three USB connections" becomes "+20 for this accountant" or "−0.7 for that field engineer", by measuring each day against the same person's own earlier days and nothing else. It also runs the go/no-go check the whole project rests on — before any model exists, do the known insiders' attack windows actually score above their own ordinary days?

Three files, 36 functions. __init__.py has none — it is a docstring and an __all__. baseline.py has 18 functions and 2 classes. test_baseline.py has 18: two fixture builders and sixteen tests.

Zone 1 — the constants and the error class

Nothing runs here. These are the numbers the rest of the file divides by and the one exception type it raises, each parked next to a comment explaining why it is that value.

signaturewhat it does
class BaselineError(AssertionError) The single exception the stage raises, for things a correct table cannot contain — a NaN, a vanished row, an attack day hidden inside a blanked opening. It inherits from AssertionError so it reads as "this was supposed to be impossible", not "bad input".
Not functions, but read them anyway. DDOF = 1 fixes the spread convention everywhere in the file, because the floor is calibrated from per-person spreads and then compared against per-day spreads — they must be computed the same way. MIN_PRIOR_DAYS = 2 is a hard floor under the warm-up: with fewer than two earlier days the formula still returns a number, and the number is "this person exists". MIN_DECAY_WINDOW_DAYS = 6 is the shortest window on which "is it fading?" is a real question.

Zone 2 — the standard-deviation floor

One function, and it is where the stage's single biggest measured decision lives.

signaturewhat it does
def std_floors(counts: pd.DataFrame, features: Sequence[str] = FEATURE_NAMES, multiplier: float = STD_FLOOR_MULTIPLIER, fallback: float = STD_FLOOR_FALLBACK, active_only: bool = STD_FLOOR_ACTIVE_USERS_ONLY) -> pd.Series ⭐ Works out one lower bound per feature for the division that comes next: take each person's own day-to-day spread in that feature, take the middle person's, keep a tenth of it. With active_only on it ignores everyone whose spread is exactly zero — otherwise the middle person is a non-user for 8 of the 18 features and the bound collapses to a flat 1.0.

Zone 3 — the z-scores

The arithmetic itself, plus the two small guards it leans on and the one call that wires the whole stage together.

signaturewhat it does
def causal_z_scores(counts: pd.DataFrame, floors: pd.Series, features: Sequence[str] = FEATURE_NAMES, min_history: int = MIN_HISTORY_DAYS) -> tuple[pd.DataFrame, np.ndarray] ⭐ For each person and feature, subtracts the average of all their earlier days and divides by the spread of those same days — today's value never enters the numbers it is being compared against. It sorts by date to compute, restores the caller's row order afterwards, and blanks each person's first 30 days to exactly zero.
def _warmup_mask(users: pd.Series, min_history: int) -> np.ndarray Marks each person's earliest N rows by counting position within that person's own block of rows, so those rows can be zeroed rather than trusted.
def _require_features(counts: pd.DataFrame, columns: Sequence[str]) -> None Fails immediately, naming the absent columns, if the incoming table is missing any of the 18 counts — instead of letting pandas fail three steps later with something unreadable.
def build_dataset(labelled: pd.DataFrame, features: Sequence[str] = FEATURE_NAMES, min_history: int = MIN_HISTORY_DAYS, active_only: bool = STD_FLOOR_ACTIVE_USERS_ONLY) -> tuple[pd.DataFrame, pd.Series, np.ndarray] The whole stage in four lines: compute the bounds, score everything, hand back a copy of the input with only the 18 values replaced. It re-selects the original column list at the end because that order becomes the neural network's channel order two stages later.
Docstring vs body. causal_z_scores' docstring says the denominator is the per-feature bound from std_floors. The body actually takes whichever is larger of that bound and the global config.STD_FLOOR constant — so a very small per-feature bound can be overridden by a project-wide one that the docstring never mentions.

Zone 4 — invariants

One function, run on every execution, whose only job is to stop the pipeline before a wrong number can travel any further.

signaturewhat it does
def verify(dataset: pd.DataFrame, labelled: pd.DataFrame, warmup: np.ndarray, features: Sequence[str] = FEATURE_NAMES) -> None ⭐ Raises if rows or columns changed, if any value is NaN or infinite, if a label column moved, if a blanked row is not zero, or if an attack day landed inside a blanked opening. Its last check — "is anything negative?" — is the one that catches raw counts being written out unscored, a bug that otherwise produces a perfectly shaped file.

Zone 5 — the validation gate

The measurement the stage exists to produce: whether the separation the models are supposed to find is present in the data at all, and what a "pass" is actually worth.

signaturewhat it does
def collapse(dataset: pd.DataFrame, features: Sequence[str] = FEATURE_NAMES) -> pd.DataFrame ⭐ Reduces each day's 18 numbers to two: the largest one ignoring sign, and the average of all 18. Both are kept because they disagree about who looks suspicious, and quietly picking one would be picking the conclusion.
def validation_gate(dataset: pd.DataFrame, warmup: np.ndarray, features: Sequence[str] = FEATURE_NAMES, threshold: float = VALIDATION_Z_THRESHOLD) -> pd.DataFrame ⭐ For each known insider, compares how loud their attack window is against how loud they were in the ordinary days before it, and returns one row per person. Run before any model exists, because no architecture can invent a separation the data does not contain.
def _gate_row(mine: pd.DataFrame, threshold: float) -> dict[str, object] | None Builds one insider's line — window length, before-and-during averages, their ratio, pass or fail under both summaries — or returns nothing at all if that person has no flagged days. The "before" days deliberately skip the blanked opening, whose structural zeros would flatter every ratio in the table.
def benign_exceedance(dataset: pd.DataFrame, warmup: np.ndarray, features: Sequence[str] = FEATURE_NAMES, threshold: float = VALIDATION_Z_THRESHOLD) -> dict[str, float] Measures how often an ordinary employee's day already clears the same bar, which is what tells you whether "the insider passed" means anything. Counts scored days only — blanked rows are zero by construction and would make the number look better.
def _late_ratio(window: pd.DataFrame) -> float ⭐ Divides the average loudness of the window's last third by its first third; below 1 means the attack is being slowly absorbed into the baseline that is watching it. Returns "not applicable" under 6 days, where the number would be day two over day one wearing a suit.
Docstring vs body, twice. _gate_row decides pass or fail on the window's average, not its peak — the peak is reported in its own column and never tested against the bar, so "insider clears 2σ" means their whole window averaged above it. And benign_exceedance' docstring still cites "54 of 70 insiders pass", a number from before the active-users correction in std_floors; the shipped run is 66 of 70.

Zone 6 — the report

Everything that turns the run into something a person can read in a terminal. No decisions are made here; if a number in this zone is surprising, the answer is upstream.

signaturewhat it does
class BaselineStats A frozen record holding the thirteen numbers the printed summary needs, so they are gathered in one pass instead of recomputed inline five times.
def compute_stats(dataset: pd.DataFrame, labelled: pd.DataFrame, warmup: np.ndarray, features: Sequence[str] = FEATURE_NAMES) -> BaselineStats Walks the scored values once and fills that record: rows in and out, people, blanked rows, flagged days, the smallest and largest and average score, and the NaN and infinity tallies.
def format_report(dataset: pd.DataFrame, labelled: pd.DataFrame, warmup: np.ndarray, floors: pd.Series, gate: pd.DataFrame, out: Path | None = None, features: Sequence[str] = FEATURE_NAMES, active_only: bool = STD_FLOOR_ACTIVE_USERS_ONLY) -> str Assembles the entire diagnostic block as one string: the counts, the denominator per feature, the insider comparison, the ordinary-day rate that makes it interpretable, and the per-person table.
def _floor_lines(floors: pd.Series, features: Sequence[str] = FEATURE_NAMES) -> list[str] One aligned line per feature — its position, its name, and the number that ended up under the division — so an implausible denominator is visible at a glance.
def _gate_summary_lines(gate: pd.DataFrame) -> list[str] The tally per attack scenario: how many insiders cleared the bar under each of the two rival summaries, the median ratios, and then the names of everyone who fell short.
def _gate_table_lines(gate: pd.DataFrame) -> list[str] The full per-insider table as indented text, sorted by scenario and then loudest first, with every number to two decimal places.
def format_user_report(dataset: pd.DataFrame, labelled: pd.DataFrame, user: str, rows: int = 20) -> str Prints one person's most extreme days with raw counts and scores side by side, so "2 USB connections" and "+20" appear in the same row. Flagged days are forced into the selection even when they are quiet, and each row names the feature that produced its peak.

Zone 7 — the CLI

One function, the only thing in the file that touches the disk.

signaturewhat it does
def main(argv: Sequence[str] | None = None) -> int Reads the labelled counts, scores them, runs the invariant checks, writes the parquet and prints the report. Its flags choose the 30-person sample or the full table — never the same output path, since a dev run once overwrote the real one — plus an optional single-person view, a CSV of the insider comparison, and the weaker denominator variant for the write-up.

3baseline/test_baseline.py

402 lines, 18 functions: two fixture builders and sixteen tests. The tests are chosen on one criterion — cover the failures that are silent. A crash is cheap. A baseline that quietly includes today in the average it is measured against costs a week and looks like a modelling problem.

Zone A — the fixture builders

Two helpers that exist so each test can say only the thing it is about.

signaturewhat it does
def make_user(user: str, values: dict[str, list[float]], days: int, start: str = "2010-01-01", scenario: int = 0, positives: tuple[int, ...] = ()) -> pd.DataFrame Builds one synthetic person's block of back-to-back days with all 18 columns present and sitting at zero, then overwrites only the columns the test names. Keeps each test readable: the one column that moves is the one under test.
def flat_floors(value: float = 1.0) -> pd.Series Gives every feature the same denominator, so a test's expected number is arithmetic the reader can do in their head rather than something derived from whoever is in the fixture.

Zone B — score against the past, never including today

The property the stage would be worthless without, and its boundary case.

signaturewhat it does
def test_spike_is_scored_against_the_pre_spike_mean() -> None ⭐ Sixty flat days then a jump to 100: the answer must equal the one you get from the earlier days alone, and must explicitly not equal the one you get if today is allowed in. That leak is a 1.6% error here and a factor of two on a short history — invisible either way.
def test_first_day_of_a_user_has_no_history_and_scores_zero() -> None With no earlier days there is nothing to be unlike, so the answer must be 0. NaN would be defensible mathematically and would end up inside a model's loss function.

Zone C — zero-variance history

The three tests that pin down what happens when someone has simply never done the thing before.

signaturewhat it does
def test_constant_history_gives_a_finite_score_when_it_changes() -> None 180 identical days then a change: the answer must be large and finite, because a large finite number is the thing worth looking at and infinity is not.
def test_a_feature_constant_for_everybody_stays_at_zero() -> None A column that never moves for anybody in the dataset gets the fallback denominator of 1.0, so it sits at zero instead of dividing by nothing the first time it twitches.
def test_the_floor_binds_only_when_it_exceeds_the_prior_std() -> None Someone with genuine day-to-day variation is measured by their own spread; the lower bound only takes over when it is the larger of the two.

Zone D — warm-up

Two tests on the opening rows: they must be blank, and nothing important may be inside them.

signaturewhat it does
def test_warmup_rows_are_exactly_zero_and_the_next_row_is_not() -> None Exactly 30 rows blanked, all of them zero, and the 31st not zero. The boundary is off-by-one bait and this is the only thing standing on it.
def test_a_positive_day_inside_the_warmup_is_a_hard_failure() -> None ⭐ An attack day inside a person's blanked opening would be emitted as an all-zero row that nothing downstream could ever detect, so the run has to stop rather than continue quietly.

Zone E — no cross-user leakage

Two tests that the grouping by person is real, and that grouping did not cost the row order.

signaturewhat it does
def test_users_are_scored_only_against_themselves() -> None A heavy user at 1000 a day and a light user at 1 a day, interleaved in one table: the heavy user's routine must stay flat and the light user's jump from 1 to 3 must stay loud. Pooled, both would be measured against ~500 and the real signal would disappear.
def test_row_order_survives_an_unsorted_input() -> None ⭐ Shuffles the input and checks each person-and-day gets the same number as before. Two things must hold at once — the maths needs date order, the next stage needs the row order it handed in — and a version that honoured only one would fail silently.

Zone F — the output contract

What the next stage is entitled to assume about the file that comes out.

signaturewhat it does
def test_shape_column_order_and_labels_survive_unchanged() -> None Same rows, same order, same column layout, values as float32, both label columns untouched. Reordering columns here raises nothing and invalidates every saved model later.
def test_verify_rejects_a_table_that_was_never_z_scored() -> None Feeds the raw counts back in as if they had been scored. Nothing else in the pipeline would object — the file has the right shape and trains about as well as noise.

Zone G — numerical stability

One test, guarding one specific rewrite someone will eventually be tempted to make.

signaturewhat it does
def test_values_around_1e8_produce_no_nan() -> None ⭐ Email-volume-sized numbers, where the textbook shortcut for spread subtracts two huge quantities and can land just below zero, which becomes NaN under a square root. This is the test that fails if anybody swaps the running averages for cumulative sums to go faster.

Zone H — the floor, and the gate

The last four: one on the measured correction in std_floors, three on the gate.

signaturewhat it does
def test_active_only_ignores_users_who_never_exercise_the_feature() -> None Eight people who never touch the feature plus one who does: the denominator must come from the one who does, rather than collapsing to the flat fallback and flattening the signal.
def test_the_gate_measures_the_window_against_the_days_before_it() -> None An ordinary life with a little noise, then a loud fortnight: the comparison must show a real rise, and benign people must not appear in the table at all. The noise matters — against a perfectly flat history the ratio would be infinite and the test would pass for the wrong reason.
def test_collapse_reports_both_max_and_mean() -> None One loud feature out of eighteen scores 36 under the largest-of summary and 36/18 under the average. That gap is the disagreement the two summaries exist to expose.
def test_an_empty_input_does_not_crash() -> None A table with no rows comes back with no rows, instead of raising — the case you hit by pointing --counts at something you filtered too hard.
One gap worth knowing. The empty-input test only exercises causal_z_scores. verify on an empty table would raise "still raw counts", because its last check asks whether any value is negative and no values means no negative ones.

4The five functions to actually remember

1

causal_z_scores

This is the thesis. Everything before it is bookkeeping and everything after it is architecture; the claim being tested is one line of arithmetic inside this function, and the word that carries it is strictly earlier.

2

std_floors

The denominator decides everything. Change how this number is computed and the insider detection rate moves from 54 of 70 to 66 of 70 without a single line of the maths changing — which is also why it is the function most likely to be "fixed" back into a worse result.

3

validation_gate

The go/no-go. It answers, before any model exists, whether the separation the models are meant to find is in the data at all — and finding that out on the last day is the one failure with no recovery.

4

collapse

Two ways to squash eighteen numbers into one, and they disagree about who looks suspicious. That disagreement is a real finding about the problem rather than a detail, and this function is where the file refuses to resolve it quietly.

5

verify

The reason you can believe the other four. Its cheapest check — "is anything negative?" — catches the failure that would otherwise be undetectable: raw counts written straight through, in a file of exactly the right shape.
