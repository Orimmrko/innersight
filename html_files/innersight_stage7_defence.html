InnerSight · Stage 7 · defence preparation

Opening the envelope once

Every stage before this one existed to make a single comparison honest. Stage 7 spends that on one pass over data no model has ever seen — and the whole of its defence is the argument that the pass really was single, really was untouched, and really did apply the decisions made before it. This document is that argument, plus the four measurements that turn it into a result.

The state of this document. The evaluation/ package is written, tested and proven end to end. The full-release runs have not happened yet, so every measured number below appears as pending. Everything that is not a measurement — the method, the pre-registered decision rules, the guards, the answers to the hard questions — is final and does not change when the numbers arrive. Fill the boxes from the run output; nothing else needs editing.

Say this first, if you say nothing else.

“The test split was opened once, for both models together, at the end. Neither model's decision threshold nor its input scaling was recomputed on it — both were saved inside the checkpoint at training time, months of decisions earlier, specifically so that they could not be. The program prints both values on every run and refuses to continue if the ones it applied are not the ones on disk.”

“And before opening it, I answered the question that decides what I am allowed to claim: not how well the model detects insiders, but when.”

Words used in this document

validationThe 200 people used to choose the stopping epoch and the decision threshold. Every number Stages 5 and 6 reported came from here. It is a selection set, so its numbers are optimistic by construction.
testThe 200 people nobody and nothing has touched. Opened once, in this stage. ~93,000 scored days per seed, ~376 of them attack days.
thresholdThe score above which a day is flagged. Chosen on validation, stored inside the checkpoint, applied unchanged to test. Choosing it on test would be the easiest cheat in the project and the hardest to spot afterwards.
standardiserThe per-feature mean and standard deviation used to scale inputs, fitted on training people only. Also stored inside the checkpoint.

1 — What Stage 7 is for

Stage 6 produced a large number: Model B scores 0.677 average precision on validation against Model A's 0.151. Stage 7 exists because that number cannot be reported as it stands, for two separate reasons.

It is a selection number

Validation chose Model B's stopping epoch, then chose its threshold, and then the same validation data was reported. Three uses of one set. Model B's per-epoch score also swings — seed 42 bounced between 0.46 and 0.71 on consecutive epochs — so taking the best of thirty-nine such epochs is optimistic on top of that. The unbiased number lives in the sealed split.

It has not been asked the question that decides what it means

Scenario-2 attacks run 45–59 days, and Model B reads the 28 days behind each day it judges. So for a day at position 30 of an attack, the entire window is inside the attack. Not a cheat — but “detects the insider” and “notices an attack it already missed” are different products, and nothing measured so far tells them apart.

2 — The rule that shapes the whole stage

Phase 1 answers every remaining question on validation. Only then does Phase 2 open the test split. The order is not negotiable and it is enforced by the program, not by discipline.

The reason is simple and total: once you have seen the test numbers, any change you make afterwards is fitting to the test set — and it does not matter whether the change was principled, because you can no longer prove it would have been made anyway. The result stops meaning anything the moment the ordering breaks.

Two mechanisms make this checkable rather than claimed. Phase 2 refuses to start unless Phase 1 has written its results file — the ordering is a missing-file error, not a habit. And every opening of the test split is appended to outputs/TEST_SPLIT_OPENED.json with a timestamp; a second opening is refused unless it is forced with a written reason, which is then recorded. A results table can be checked against the number of times test was read.
The line to use if asked “how do we know you only looked once?”

“You can check. There is a file that records every time the test split was opened, with a timestamp and a reason, and the program appends to it before it reads a single row. A second pass requires forcing it and writing down why, and that reason ends up in the file. I cannot prove I did not delete the file — but I can point at a design where deleting it is the only way, rather than one where nobody would ever have known.”

3 — The measurement that decides what the project may claim

This is the most important analysis in the stage, and it is not about accuracy at all.

Is Model B detecting the insider, or noticing that an attack it already missed is still running?

Roughly half of all scenario-2 attack days sit deep enough inside a 45–59 day window that Model B's entire month of context is itself attack behaviour. Seeing 28 consecutive anomalous days and concluding “attack” is easy. Seeing day one and concluding “attack” is the product.

First, what this is not. It is not leakage. The window reaches strictly backwards, contains only that same person's rows, and no label is ever visible to the model at any point. Being shown a person's own recent behaviour is precisely what temporal context means; that the behaviour was also anomalous is the signal rather than a cheat. This distinction matters, because “leakage” and “a weaker claim than you think” call for completely different responses and only the second one applies.

Two views, both from predictions that already existed

First detection. For each insider: the earliest day that is both labelled an attack day and scored above that checkpoint's own threshold, expressed as day N of that insider's attack window. Insiders never detected at all are counted separately — they are a result, not missing data.

Recall by position. The same attack days, bucketed by how far into the attack they fall.

At the same time Model B's window fills up with attack days, which argues for it. The two effects run opposite ways and only the measurement settles which wins.
The line to use whichever way it lands

“I raised this against my own result before anyone else did, I wrote the decision rule down before I could see which answer it would give, and the report states the claim that rule licenses — not the one I would have preferred.”

4 — The capacity control: is it context, or is it just bigger?

Model B has 7.6× Model A's parameters. “B wins because it is bigger” is a live alternative explanation for the entire project, and it deserves a control rather than a paragraph.

The clean separation is Model B on a seven-day window. Convolutions followed by a global average do not care how long the sequence is, so ModelB(days=7) has exactly the parameter count of ModelB(days=28) — 4,897 either way. Same architecture, same capacity, one quarter of the context. Seven days is the floor, because the two dilated kernel-3 layers have a seven-day reach and anything shorter would leave the second layer convolving over padding.

Every one of those three outcomes is a result. This is not a check that is hoped to pass — it is a measurement that produces a sentence either way, and the run aborts before training if the two parameter counts are ever unequal, because the control separates nothing if capacity is allowed to move.
And it is never scored on test. It is a control, not a competing model. Its checkpoints are written under a separate tag, and the loader that opens the reported models physically refuses to open them.

6 — The nine rows that outscored almost every real attack

Stage 6 left one anomaly explicitly unresolved. Model B seed 123 scored P@50 = 0.520 but P@10 = 0.100 — nine of its ten highest-scoring validation days are labelled benign, yet they outrank nearly every genuine attack day. Stage 7 prints those rows and reads them.

There is a measured reason to suspect the labels rather than the model. Stage 2 established that the published attack windows mark the signature event, not the full behavioural anomaly. BIH0745's heaviest after-hours USB copying sits outside his 65-minute labelled window. KPC0073's loudest day in the entire dataset — z = 107 on after-hours USB — is formally labelled 0. A model that ranks such days at the top is not wrong about the behaviour; it disagrees with the annotation.

Each inspected row is classified into one of four readings, and the sentence the report uses is derived from the counts rather than chosen first:

ReadingcountWhat it would license
insider, inside the window's dates but unlabelled—“Our highest-scoring false positives are genuine anomalous behaviour the ground truth fails to label. The reported precision is therefore a lower bound.”
insider, within 28 days of their window—
insider, far from their labelled window—unlabelled anomalous behaviour by a known insider — the Stage 2 finding, restated on new data
a person with no labelled attack at all—genuine false positives — an honest failure mode, and precision should be read at face value
Both answers are reportable and only one of them is flattering. That is the point of deciding the wording from a count. The alternative — looking at the rows, forming an impression, and then writing the sentence — is how a report ends up claiming a lower bound because the author wanted one.

Those are Stage 4's measurements, printed back as a guard. If the shape has drifted, the splits file and the dataset have gone out of step — a failure no accuracy figure would reveal.

The guard that fails on a good-looking number. If either model scores a test AUPRC at or above 0.95, the program treats it as leakage rather than success and exits with an error code instead of writing a results file. At a 0.4% positive rate with labels this coarse, near-perfect ranking means a split applied by row instead of by person, a scaler fitted on everything, or a label leaking into a feature. This is the guard most likely to be argued with, which is exactly why it is enforced in code.
And the honest expectation. Test AUPRC should land near the validation figures. A large gap in either direction is a finding to investigate and report, not to smooth over — and a test score meaningfully above validation is more suspicious than one below it.

8 — The AUROC / AUPRC gap, as a finding rather than a footnote

This is worth raising unprompted, because it is the clearest statement in the project about why the metric was chosen.

Model A, validation0.93830.15130.0043

LAN (Cai et al., 2024), r4.20.9369not reported—

Model A scores 0.938 AUROC — level with recent published work on this dataset — and 0.151 average precision on the same predictions.

Both numbers are correct. At a 0.4% positive rate, AUROC is dominated by the ease of ranking hundreds of thousands of obvious negatives, so a model gets rewarded for correctly ignoring the days nobody was ever going to look at. Average precision describes what an analyst with a finite queue actually experiences.

The LAN comparison is an anchor, not a like-for-like: it uses a temporal split and a different labelling scheme. The point survives the caveat — a one-day model with essentially no ability to see a trend already reaches the AUROC the literature quotes.

10 — How “we did not peek” is made provable

Six checks run on every pass and print their values rather than a verdict. A boolean saying “the scaler came from the checkpoint” is exactly as convincing as no check at all.

The scaler is the one the weights were trained under

The mean and standard deviation are refitted from the training people and compared, to nine decimal places, against the values stored in each checkpoint — and both models' stored values are compared against each other. The guard prints the actual numbers. A mismatch means either the dataset changed since training or the checkpoint is not what it claims, and either way the comparison is void.

The threshold is the one chosen on validation

Compared byte-for-byte against the stored value and printed, along with how many days it flags. The code that would choose a threshold is not imported into the evaluation package at all.

Both models scored the identical rows

Compared by a hash of every row's person, day and label — not by a row count. A count catches a dropped row; a hash also catches a reordering, which is the failure that would leave both scores plausible and both wrong.

Test people appear in no training or validation split

Checked per seed. A person who trains under seed 42 and is tested under seed 123 is fine — those are independent experiments. A person who does both within one seed invalidates that seed.

No NaN, no infinity, and every score above the random baseline

And the one that makes the rest believable

Re-scoring validation from the checkpoints must reproduce the AUPRC that Stages 5 and 6 logged. If loading the weights, rebuilding the architecture, applying the stored scaler and applying the stored threshold gives back 0.1237 / 0.1687 / 0.1615 for Model A and 0.7127 / 0.6306 / 0.6868 for Model B, then the identical machinery pointed at test is doing what it says. On the 30-user smoke run it matched to four decimal places on all six checkpoints.

The line to use

“I did not write a check that says the scaler came from the checkpoint. I wrote one that refits it from the training people, compares it to nine decimal places, and prints both sets of numbers into the log and into the results file. You can read them.”

11 — Weaknesses, said before anyone asks

The dataset is synthetic and deliberately dense

Seventy insiders among a thousand people is a 7% rate no real organisation has. The per-day positive rate of 0.4% is realistic; the per-person rate is not, and it makes the training problem easier than reality.

Three of the eighteen features carry nothing on this release

large_attachment_count is identically zero across r4.2, and two others barely move. The model is effectively working with fifteen.

The labels are windows, not events

Every day inside an attack window is labelled positive, including days on which the insider did nothing unusual — and, as §6 shows, some genuinely anomalous days sit outside the window and are labelled benign. Both directions of error are present, and neither can be fixed without re-labelling by hand.

Scenario 3 rests on four test rows per split

Arithmetic, not bad luck: all ten of those insiders have exactly two attack days each. A recall there has five possible values, and its standard deviation across seeds measures noise on four rows and nothing else. It is written as “n of 4 attack days” everywhere, never as a percentage.

The standard-deviation floor is a population statistic including test people

Stage 3's per-feature floor is a median of per-user standard deviations taken over everybody. Any one held-out person contributes roughly 0.1% of it. It is bounded, it is disclosed, and it is not worth re-running the pipeline over — but it is not zero, and it should be stated rather than discovered.

The three seeds are three splits, not three initialisations

So “mean ± sd” here measures the split lottery rather than model variance. That is the more conservative of the two and the right one to report at this sample size, but it is not an ensemble and should not be described as one.

The tuning attempt is excluded, deliberately and visibly

Model B v2 lost — 0.6767 down to 0.6022 with double the spread — and appears nowhere in the results. It survives as one paragraph, because why it lost is a finding: adding a maximum channel to the pooling raised scenario-1 recall 6.6 points and cost 11.0 points of scenario 2, which is 88% of positives. The pooling operator selects which attack profile the model can detect. Sustained pooling for a drift, peak pooling for a burst, and at 4,900 parameters you cannot have both.

12 — Questions to rehearse

How do I know you didn't try several thresholds on the test set and report the best one?

Because the threshold was chosen on validation months of decisions earlier and written inside the checkpoint file, alongside the weights and the input scaling. Stage 7 loads it and applies it. The function that searches for a threshold is not imported into the evaluation package — there is no code path that could sweep one on test.

And it is not left as an assurance. Every run prints the threshold it applied beside the value stored on disk, compares them, and refuses to continue if they differ. The same is true of the scaler, which is additionally refitted from the training people and compared to nine decimal places. Both sets of numbers are in the log and in the results file.

Scenario-2 attacks last two months. Isn't Model B just seeing the rest of the attack?

That is the strongest challenge to this result and I would rather raise it myself. It is not leakage: the window reaches strictly backwards, contains only that same person's rows, and no label is ever visible. Being shown someone's own recent behaviour is what temporal context means.

But whether it catches the onset or merely notices an attack in progress is a real question, and it is the first thing Stage 7 measures. I plot recall against the day's position inside its own attack window, with the decision rule written down before I could see the answer. If recall climbs steeply with position, the claim changes from “detects insiders” to “identifies ongoing exfiltration campaigns” with the median latency stated — and the report generates that wording automatically from the measurement, so I cannot quietly keep the stronger claim.

Model B is 7.6 times larger. Is it winning on context or on capacity?

I ran the control. The same architecture on a seven-day window has exactly the same parameter count — 4,897 — because convolutions followed by a global average do not care about sequence length. So the only thing that changes is how far back it can see, and the run aborts before training if those two counts are ever unequal.

If it lands between Model A and Model B, capacity is ruled out and context is demonstrated. If it lands level with the 28-day model, capacity was doing the work and I say so. I did not run a control I expected to pass; I ran one where all three outcomes produce a sentence I would have to write.

Your AUROC is 0.99. Isn't that too good?

It is, in the sense that it is the wrong number to be impressed by. Model A — which sees a single day and structurally cannot detect a trend — already scores 0.938 AUROC, level with recent published work on this dataset. On the very same predictions its average precision is 0.151.

At a 0.4% positive rate AUROC is dominated by how easy it is to rank hundreds of thousands of obviously ordinary days. It rewards a model for correctly ignoring the days nobody would ever have looked at. I report both, headline the average precision, and print the random baseline of 0.004 next to it every single time, because “0.68 against a baseline of 0.004” is a sentence you can evaluate and “0.68” is not.

What would have made you say the thesis failed?

Two things, and both were written down in advance. If Model B had improved the sharp bursts and left scenario 2 where it was, the 28-day window would have been adding capacity rather than context, and the thesis would not have been supported — scenario 2 is the attack type that is defined by playing out over weeks.

And in this stage: if the seven-day control recovers the whole gain, the honest conclusion is that the architecture rather than the history is doing the work. That control exists precisely because it could produce that answer.

You have a whole document of guards. Isn't that over-engineering for a student project?

Every one of them exists because of a specific way this project could produce a plausible number and no error. A model that collapses to “nobody is an insider” is 99.6% accurate and its loss curve looks perfectly healthy. A scaler refitted on the evaluation rows raises the score and raises no exception. Two models scored on slightly different rows still give two numbers you can put in a table.

The check I would point at is the one that re-scores validation from the checkpoints and compares against what the training runs logged. If that reproduces to four decimal places, the same machinery applied to the test split is doing what it claims. That is not decoration — it is the reason to believe anything else in the results.

Why is the tuned Model B not in the comparison?

Because it lost, and including a variant only when it wins is how a report becomes a sales document. It scored 0.6022 against 0.6767 with double the spread. The code was reverted; the measurement was kept.

What is in the write-up is the reason it lost, because that is a real finding. Adding a maximum channel to the pooling gave the model the shortcut “find the single worst day” — the right instinct for a two-day burst and precisely the wrong one for a drift whose individual days are unremarkable. Scenario 1 gained 6.6 points and scenario 2 lost 11.0, and scenario 2 is 88% of the positives. The pooling operator chooses which attack profile you can detect.

What is the one thing you would do next?

Run this on r5.2. It has two thousand people, exercises all eighteen features rather than fifteen, and adds a fourth attack scenario — so it separates “the method works” from “the method works on r4.2”, which is the single largest thing this project cannot currently claim.

After that, three weight initialisations within each split, so the error bars measure model variance rather than the split lottery; and attention pooling in place of the mean, which would keep the drift sensitivity while producing a per-day weight map — turning “this person is anomalous” into “these are the days that made them anomalous”, which is what an analyst opens the alert to see.

The sentence to end on.

“Six stages went into making one comparison honest: one row set for both models, one scaler fitted on training people only, one training loop that does not know which model it is running. Stage 7 spends all of that on a single pass over two hundred people nobody had touched, with the threshold and the scaling taken from files written before that data was ever opened. The result is — against a random baseline of 0.004, and — more importantly — I can tell you when in an attack it arrives, because I measured that before I was allowed to see the test set at all.”
